# Рабочее пространство с сервером

Новый интерфейс обслуживает FastAPI, главная страница `/`. Он использует реальные фоновые задания, хранение проектов и прежний сборщик. Это один рабочий кабинет для владельца и совместного разбора, без разделения данных между несколькими пользователями.

## Локальная проверка

Установите зависимости из `app/requirements.txt` и `stage_3/code/requirements.txt`, затем `python -m app --port 18106`. Откройте http://127.0.0.1:18106/ . Не нужно переносить ключ ProxyAPI: базовая версия не вызывает модель.

## Подготовленный вариант общего размещения

Docker-контейнер: Python 3.12 / FastAPI, непривилегированный процесс, порт 8000, отдельный постоянный том `/data`. HTTPS завершает существующий обратный прокси владельца сервера. Рекомендуемый адрес — отдельный поддомен сервера, согласованный с владельцем. Имеющиеся приложения не заменяются.

Серверный вход `app.server:app` откажется запускаться без переменных `ANALYST_ALLOWED_HOSTS` (точный домен, без схемы) и `ANALYST_PASSWORD` (пароль рабочего кабинета). Имя входа `analyst`. Секрет задаёт владелец в конфигурации сервера; файл с ним не включать в Git. Пароль нельзя передавать по HTTP: внешний адрес должен иметь действующий HTTPS. При обратном прокси настройте доверие к его forwarded-заголовкам только для фактического адреса прокси, иначе проверка Origin будет отклонять запись.

Перед публичным запуском нужно подтвердить сервер и адрес, проверить наличие Docker, свободные ресурсы, DNS, HTTPS, постоянный том и ограничения внешних запросов. Открытый многопользовательский сервис потребует раздельных кабинетов, квот и очереди задач; этот вариант предназначен для защищённого совместного просмотра. Docker-образ ещё не считается проверенным, пока сборка и запуск не выполнены на доступном движке. Сейчас общая серверная ссылка не опубликована.

Тариф нового хостинга не выбран, платные ресурсы не заказывались. GitHub Pages не используется как Python-сервер. Демонстрации прежних этапов остаются отдельно.

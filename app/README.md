# Локальный API и история запусков

Расширение использует движок `stage_3/code/analyst.py`. Каждый запуск получает UUID, отдельную папку с отчётами и запись в SQLite. История сохраняется после перезапуска. Настройки, статус, число наблюдений и SHA256 входного манифеста доступны через API; источники и цитаты — в JSON-отчёте. Ошибки сохраняются без текста исключений и секретов. Стенд доступен локально по `/stand/stage3.html`, документация API — по `/docs`.

## Запуск

Из корня `competitor-neuro-analyst`, Python 3.10 или новее:

```powershell
python -m pip install -r app/requirements.txt
python -m app
```

Открыть http://127.0.0.1:18105/docs — интерактивная документация с кнопкой Try it out. Сервер слушает только локальный адрес. Отдельного публичного размещения API нет; GitHub Pages исполнять Python и хранить SQLite не может.

На текущем компьютере зависимости установлены отдельно в `../Служебное/api-libs`. При использовании встроенного Python Codex нужно добавить эту папку в `PYTHONPATH`.

## Применение

1. `GET /companies` — идентификаторы компаний.
2. `POST /runs` с телом `{"country":"Portugal"}` — анализ всех согласованных конкурентов. Для подмножества добавить `"competitors":["migrun"]`; пустой список оставит свою компанию.
3. `GET /runs` — история; `GET /runs/{id}` — карточка запуска.
4. `GET /runs/{id}/report?format=html` — скачать отчёт. Другие форматы: `json`, `csv`, `md`.

Рабочие данные находятся в `var/history.sqlite3` и `var/runs/{id}/`; они исключены из Git. Каждый отчёт содержит ограничения покрытия. Португалия: 9 критериев, 30 наблюдений, 3 гипотезы для полного выбора 11 конкурентов. Испания: наблюдений в текущем пилоте нет. Используются снимок 22.10.2026 и четыре дополнительные страницы 04.11.2026. Новых вызовов LLM и расходов на API нет. Неизвестные компании, повторяющиеся ID и дополнительные параметры отклоняются.

## Что взято из урока

Источник: [PEm08 — проект мультимодального приложения](https://university.zerocoder.ru/pl/teach/control/lesson/view?id=345590328), текстовые пояснения и репозитории [примера](https://github.com/Toxap/pem08) и [вашей работы](https://github.com/gorlanova-automation/pem08-competition-monitor), просмотрены 02.11.2026.

Применены API поверх отдельного аналитического движка, строгая схема входного JSON, сохраняемая история и отдельные результаты каждого запуска. Вместо единственного перезаписываемого файла истории используется SQLite. API проверяется через [FastAPI TestClient](https://fastapi.tiangolo.com/tutorial/testing/).

Из замечания куратора взята проверка качества визуального источника. Перед будущим анализом скриншота необходимо:

1. Записать URL, компанию, время получения и страну страницы.
2. Открыть изображение и проверить, что виден нужный раздел, загрузка закончена, а cookie-баннер, чат или модальное окно его не закрывают.
3. Если содержимое закрыто — переснять страницу либо отметить источник как непригодный. Не выдавать анализ перекрывающего окна за анализ сайта.
4. Отделять наблюдения на изображении от предположений модели, сохранять ссылку на оригинал и результат ручной проверки.

Это пока ручной протокол: загрузка изображений, автоматическая проверка перекрытий и мультимодальные вызовы в API не реализованы. Selenium, PDF, аудио и desktop-приложение не добавлялись: текущему этапу хватает существующего сбора текстовых источников и локального API. Модели и цены из учебного примера не перенесены без отдельного сравнения качества и стоимости.

## Проверка

```powershell
python -B -m unittest app.test_api -v
python -B -m unittest discover -s stage_3/code -p test_analyst.py -v
```

Тесты проверяют сохранение истории после перезапуска, отдельные файлы двух запусков, результаты для двух стран, ссылки на доказательства, ограничения входа, безопасную регистрацию ошибки и запрет межсайтовых запросов записи.

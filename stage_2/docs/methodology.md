# Методика и критерии готовности пилота

## Реальное выполнение

Первый программный запуск: `runs/20261021T191729Z_4005ca`. Python получил восемь страниц двух компаний, сохранил исходный HTML, очищенный текст, реестр и 22 фрагмента. Все восемь ответов HTTP 200, после проверки robots.txt. Это сбор сайтов, а не сбор соцсетей или выводы LLM.

## Очистка

BeautifulSoup удаляет script/style/noscript/svg/template/head/form/nav/footer, нормализует пробелы и HTML-сущности. Ссылки сохраняются до удаления элементов. Повторяющиеся текстовые строки не удаляются глобально: одинаковая цена в двух карточках относится к разным предложениям. Точный дубликат целой страницы отмечается по хэшу. URL очищается от фрагмента, query сохраняется, поскольку он может менять содержание. Ограничения: статический HTML может содержать невидимые меню/модальные блоки; в нём может не быть динамически подгруженного содержания. HTTP 200 не гарантирует полноту. Изменения алгоритма очистки должны получать новую версию и повторную контрольную проверку.

Первые четыре страницы на компанию выбираются из заданных начальных URL и обнаруженных релевантных ссылок. Это ограниченный пилот, а не весь сайт. Фрагменты до 7000 символов, перекрытие 600; реальные смещения и хэши сохранены. Перекрытие может порождать повторные факты; удаляются только точные дубликаты записей, противоречия сохраняются.

## Контроль

Ручная контрольная выборка: восемь опубликованных цен с двух страниц услуг. Подготовлена ассистентом до модельных запросов по фактическому сохранённому тексту. Среди примеров специально оставлены две разные цены налоговой консультации на одной странице Immigration Relocator. Их нельзя автоматически усреднять или выбирать «правильную».

Сравнение A/B: baseline_v1 и evidence_v2, одна модель, одинаковые два фрагмента, одна схема и настройки. Вторая версия добавляет правила привязки цены к услуге, инвестиционных порогов, рекламных показателей и точной цитаты. Оба опыта выполнены: каждый сохранил 8/8 контрольных цен. Изменение количества фактов не является измерением смысловой точности.

Автопроверки: JSON Schema, точная цитата в исходном фрагменте, непустое значение, цена с названием услуги/суммой/валютой, показатели доверия остаются заявлениями компании. Ошибки идут в карантин; некорректный ответ модели не маскируется пустым успешным результатом. Проверка слов/сумм на контрольных примерах — вспомогательная оценка полноты подвыборки. Смысловую точность оценивает человек по каждой принятой записи и её контексту. Все принятые записи изначально pending_human_review.

Критерий перехода к расширению: обе компании успешно получены, оба промпта реально вызваны, контрольные цены сверены, существенные ошибки и ложные факты разобраны; при ошибках исправить код/промпт и повторить эксперимент на том же корпусе. Массовый сбор по всем девяти автоматически не стартует до этой проверки.

## Происхождение и отсутствующие данные

Три отдельные категории: manual_preparation, python_requests, llm_extraction. Ручные контрольные примеры не выдаются за результат LLM. Заявления сайта — company_claim, опубликованные предложения — published_offer; независимая проверка лицензий/отзывов пока не выполнена.

Пропуски фиксируются «не найдено в исследованных источниках» только после перечисления реально исследованного корпуса и категории. По неоткрытым соцсетям — «не исследовано/недоступно», а не «публикаций нет». Ни полный ассортимент, ни качество услуги, ни конверсия/выручка по этому пилоту не установлены.

## Внешние источники

discovered_links.json сохраняет найденные ссылки и сайт-основание. Одна ссылка с сайта — признак принадлежности, ещё не полная проверка аккаунта. external_queue.json содержит запланированные проверки, статус pending не означает сбор.

Для соцсетей нужны: обнаружение по сайту и поиск внутри площадки; проверка домена/контактов/обратной ссылки; официальный аккаунт подтверждается человеком при сомнениях. Личные профили и закрытые группы не включаются. Период — 90 календарных дней включительно по дату сбора, до 20 последних оригинальных публикаций каждого подтверждённого публичного аккаунта. Для каждой публикации сохраняются URL, дата публикации, время сбора, текст/описание, формат, тема, способ обращения; количество доступных записей и фактический диапазон. Ограниченная лента не равна полной выборке. Адаптер публичного Telegram-превью получил 25 публикаций двух каналов; полнота и принадлежность требуют проверки. Другие соцсети остаются в очереди.

По Google/Яндексу сохраняются движок, точный запрос названия, язык, регион, профиль/авторизация, время и первая видимая страница результатов без рекламного взаимодействия. Созданный URL поиска не является полученной выдачей. Карта проверяется отдельно по домену, адресу и названию; оценки и отзывы считаются внешними мнениями, а не доказательством качества.

### Проверка цитат после первого модельного запуска

Автоматическая проверка подстроки не доказывает, что цитата подтверждает всё значение. В evidence_v2 обнаружена запись 71607822294db7a50a2d: value перечисляет D8/D7/D2/D3, но её evidence содержит только заголовок «Оформление визы и вида на жительство (ВНЖ) в Португалии». Это дефект полноты доказательства, даже если типы виз упомянуты в других местах исходной страницы. Полная смысловая точность не рассчитана.

В базовом промпте некоторые цены подтверждаются только суммой. После сохранения исходных экспериментов валидатор усилен: цитата, содержащая исключительно сумму/валюту, отправляется в карантин. Это консервативная проверка, она не доказывает правильность всех остальных связей. Исторические результаты не перезаписываются; для сравнения старые модели использовали одинаковый исходный валидатор. Добавлен регрессионный тест, проверки сохранены в code/test_collector.py.

# Приложение: от сайта к отчёту

## Запуск на компьютере

Из корня репозитория:

```sh
python -m pip install -r stage_3/code/requirements.txt -r app/requirements.txt
python -m app
```

Откройте http://127.0.0.1:18105/ . Приложение слушает только этот компьютер.

1. Введите сайт. Если получить страницу не удалось, предоставьте её текст через TXT или вставку. Его происхождение будет указано отдельно.
2. Исправьте черновик профиля: название, предложение, рынок и поисковые слова. Подтвердите его.
3. Попробуйте поиск кандидатов либо введите известные адреса. Проверьте соответствие компаний и подтвердите список. Скриптовые кандидаты и добавленные пользователем сохраняются с разными отметками.
4. Запустите сбор. Откройте HTML или скачайте JSON. В отчёте есть цитаты, URL, хэши источников, недоступные страницы и ограничения.

Черновик профиля использует метаданные страницы. Автоматическая выборка цитат использует текстовые правила. Это не смысловой анализ модели и не оценка эффективности маркетинга. Ссылки на социальные площадки не означают прочитанные ленты. Визуальные свойства по HTML не определяются.

Для смыслового анализа предусмотрен отдельный вызов `run_project(action='analyze', ...)` в финальном Colab. Ключ получает только Colab из `PROXYAPI_KEY`: его нельзя вставлять в ноутбук, URL, GitHub или публичный интерфейс. Один запуск — один запрос, не более 2500 токенов ответа, без автоматического повтора. Ответ проверяется на точные цитаты и существующие источники. Он остаётся модельным черновиком до проверки смысла человеком. Неудачный ответ сохраняется в карантине; предыдущий отчёт остаётся доступен.

## Где хранятся проекты

`var/projects/<UUID>/state.json` — состояние и подтверждения. `own_source.json` — снимок, к которому привязан профиль. Каждый сбор и модельный анализ создают отдельную папку `runs/<UUID>/` с исходниками и отчётом. Папка `var/` не публикуется в GitHub. Удалять или редактировать её для обычного повторного запуска не требуется.

Публичный GitHub Pages показывает сохранённые исследования. Он не исполняет Python и не получает API-ключ. Страница `workspace.html` распознаёт отсутствие сервера и показывает инструкцию запуска.

## Проверка

```sh
python -B -m unittest discover -s stage_3/code -p 'test_*.py'
python -B -m unittest stage_4.test_workflow stage_4.test_semantic app.test_api app.test_workflow_api -v
```

Тесты с подставленным транспортом помечены `injected_test` и не считаются реальными вызовами модели. Демонстрация `run_saved_demo` использует ранее собранные тексты; автоматические подтверждения в ней явно названы демонстрационными.
